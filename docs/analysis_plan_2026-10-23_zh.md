# 方向C 预注册（2026-10-23，在任何方向C实验之前写定）

## 0. 背景（已有证据，来自PLOS项目，非本文新结果）
- YOLO11n@896 s0，NX TensorRT 8.5 隐式PTQ（Entropy2，INT8-full）：test AP 54.14，FP16 68.10，延迟 10.20 vs 13.85 ms。
- 640 下 Entropy INT8 观察到输出分数被压缩（最高分约0.897）。
- 这些数字只作动机；本文所有结论来自本项目新跑的实验。

## 1. 研究问题
Q1 INT8 精度损失从哪来（哪些层/组、哪类目标尺寸、是否为输出分数压缩）？
Q2 强PTQ（校准器、校准集、少量FP16例外层）能补回多少？
Q3 QAT（从已有FP32权重微调）相对最佳PTQ能否再提升？
Q4 若剩余损失集中在小目标，小目标感知的QAT变体是否有效？

## 2. 模型与数据
- FP32 权重：服务器 edgets/runs 中 YOLO11n@640/896/1024/1280 的 s0–s4 best.pt（只读引用，不改）。主分辨率 896 与 1024；640 为辅。
- TT100K45：train 5489 / val 610 / test 3071。所有选择（校准器、校准集、例外层、QAT超参、变体）只用 val。test 在最终配置冻结后每个配置只评一次。
- 校准图像只取自 train。

## 3. 量化方案
- W8A8：权重 per-channel 对称，激活 per-tensor 对称（与 TensorRT 显式 Q/DQ 兼容），NVIDIA ModelOpt 伪量化。
- 云端（RTX 4080 SUPER, TensorRT 10.13）只用于精度；NX（TensorRT 8.5）上的延迟/功耗/构建可行性以后补测，论文中分开报告。

## 4. 评估协议
- 输入方形 letterbox（不用 rect），conf 0.001，NMS IoU 0.7，max_det 300；COCO AP 由 pycocotools 计算；同时报告 AP_S/M/L 与按 GT √面积 分档（<32, 32–64, ≥64 px，原图尺度）的召回/AP。
  - 修订（2026-10-23，仍在任何实验之前）：原写“最长边 <16/16–32/32–64/≥64”，但 val 中 <16 px 只有 36 个 GT，统计量太小；改为 √面积三档（val GT 数 596/535/326）。
- 同一协议用于 FP32、PTQ、QAT 所有条件。

## 5. Go/No-go（G2 结束时按 s0、val 判定）
设 gap = AP(FP32) − AP(最佳PTQ)，最佳PTQ 允许 FP16 例外层不超过全部卷积层数的 10%。
- No-go（QAT不立项，论文转为PTQ分析）：896 与 1024 的 gap 都 ≤ 1.0 AP。
- Go：任一主分辨率 gap ≥ 3.0 AP；或 gap > 1.0 且小目标（AP_S）损失 ≥ 2 × 大目标（AP_L）损失。
- 其余情况为灰区：停下与作者讨论后再决定，讨论结果记入 experiment_log。

## 6. QAT 成功判据
- 主判据：5 seed 平均、逐 seed 配对，QAT val AP − 最佳PTQ val AP ≥ +1.0（896 与 1024 分别判定）。
- 小目标变体（G5）：相对QAT基线 ΔAP_S ≥ +1.0 且总AP不降超过 0.3。
- 超参只用 s0 在 val 上选，定型后不再改。

## 7. 诚实性约定
- 若判据未满足，按实际结果写，不事后放宽判据；任何事后分析标注为 post-hoc。

## 8. 补充预注册（2026-10-24，写于 G4 之后、G5 与 NX 实验之前）
背景：G4 的 5 个 seed 结果已知，官方 QAT 没有满足 §6。作者决定进入 G5。本节在任何 G5 或 NX 实验开始前写定，属于对原计划的事后补充，论文中会如实说明这一点。

### 8.1 G5 候选（只做这 3 个，不临时增加）
基线为官方 QAT（Ultralytics 8.4.166，quantize=8，lr0 2e-4，20 epoch，其余设置与 G4 相同）。
- C1 percentile 初始化：用 512 张随机选取并 letterbox 的 train 图像做 histogram 校准，激活取 percentile 99.99（官方做法是 8 个 mosaic 训练 batch 加 max 校准）；FP16 例外层与官方相同。
- C2 去掉 mosaic：从第 1 个 epoch 起 mosaic=0，其余与基线相同。
- C3 小目标加权输出蒸馏：教师为原始 FP32 模型（冻结）。对 Detect 各层每个 anchor 的 DFL 分布做 KL 散度、对 cls 做以教师 sigmoid 为目标的 BCE，按教师最高类别分数加权，P3（stride 8）层的权重再乘 λ=2。总损失为检测损失加 dis 乘蒸馏损失，dis 固定为 1.0，不调。
### 8.2 筛选与确认
- 筛选：每个候选在 s0 上训练，896 与 1024 各一次，只看 val。若某候选在两个分辨率上的 AP 均值比官方 QAT s0 高出 ≥0.3，且 AP_S 不下降，则进入确认阶段；有多个满足时只取一个，选 ΔAP_S 均值最大的。若没有候选满足，G5 记为阴性结果，论文走“机理与部署分析”路线。
- 确认：胜出者补跑 seed 1–4，与官方 QAT 做逐 seed 配对比较。成功判据沿用 §6：ΔAP_S ≥ +1.0，且总 AP 下降不超过 0.3，896 与 1024 分别判定。
- 若 C3 胜出，再补一个 λ=1 的消融（5 个 seed），用来区分“蒸馏”和“P3 加权”各自的作用。这个消融只做报告，不改变判定结果。
### 8.3 NX 测量协议（Jetson Xavier NX，L4T R35.6.5，TensorRT 8.5.2.2）
- 模式：nvpmodel mode 8（20W 6CORE）加 jetson_clocks。每次测量前检查：gdm3 未运行、CPU 空闲 ≥90%、空闲时 VDD_IN 约 4.8 W。
- 引擎：batch 1，静态输入，896 与 1024，s0 权重。配置包括：FP16；INT8 显式 Q/DQ，分为全量化、PTQ-E7、PTQ-greedy8（s0 排序）、官方 QAT、G5 胜出者（如果有）。另做一个隐式 Entropy2 INT8 作为与 PLOS 一致的参照。
- 延迟：trtexec --iterations=1000 --warmUp=2000 --avgRuns=100，读 "Latency" 的 mean/median/P99（PLOS 规范）。每个引擎测 2 次，取均值。
- 功耗：tegrastats 以 100 ms 间隔记录 VDD_IN，运行 trtexec --duration=30；能耗 = 平均功率 / 吞吐量。
- 精度：在 NX 上用同一引擎跑 val，协议同 §4，用来核对与云端伪量化的一致性。test 只在最后各评一次。
- 若某个 Q/DQ 引擎构建失败，或 INT8 层比例异常，如实记录，不更换方案回避问题。

## 9. 补充：机理泛化检验（2026-10-30，G5 判为阴性之后、实验开始之前写定）
- 目的：检验 G1/G2 的机理结论是否不止适用于 YOLO11n。待检验的结论有两条：(1) INT8 损失主要来自定位（AP75、AP_S 掉得多于 AP50）；(2) 最敏感的部位是 Detect 头的 box 分支输出卷积和 DFL。本节是描述性检验，不设通过/失败门槛，结论按实际结果写。
- 模型（全部是已训练好的 s0 权重，不再训练，只读引用）：
  - YOLOv8n@640（有 DFL 头，与 YOLO11n 同类）
  - YOLO26n@640（reg_max=1，没有 DFL，可作为反例检验 DFL 的作用；评估时用 one2many 分支并走同一套 NMS 协议）
  - YOLO11s@1280（模型更大、输入分辨率更高；这组权重由方向 A 项目训练，本节只读使用）
- 方法：与 G1、G2 完全相同。ModelOpt W8A8 伪量化，校准用 512 张随机 train 图；激活范围比较多种方法，分组做敏感度测试；固定例外集与 LOO 贪心都以 8 个卷积为上限；全部在 val 上评估。
